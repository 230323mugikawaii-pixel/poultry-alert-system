# 通知メンバー基盤

## 利用人数

画面上の `seatCount` は代表者を含む合計利用可能人数です。既存DBの
`Subscription.seatLimit` は追加利用者枠として維持し、次の対応にします。

- `seatCount = 1 + seatLimit`
- 代表者は1人で、追加枠を消費しない
- 追加枠はACTIVEな既存Team MEMBERとACTIVEな通知メンバーの合計で消費する
- 空き枠は `max(seatLimit - occupiedAdditionalSeats, 0)`

この対応により、既存の料金計算と契約変更処理を変更せず、利用者向けには代表者を
含む人数で表示できます。減員時に現在の利用者数が新上限を超える場合は既存どおり
保留し、通知メンバーの利用停止で条件を満たした時点に適用します。

## 認証情報

- Call Now IDは `CN-XXXXXXXX` 形式で暗号学的乱数から発行する
- 初期パスワードと再発行パスワードは応答時に一度だけ表示する
- DBにはArgon2idハッシュだけを保存する
- 通知メンバーのセッショントークンはHMAC-SHA-256でハッシュ化して保存する
- 通知メンバーCookieはOWNER用Cookieとは分離し、HttpOnly、SameSite=Lax、Path=/とする
- staging/productionではSecureを有効にする
- ログイン試行制限はPostgreSQLの共通カウンターで、接続元、Call Now ID、両者の組を制限する

パスワード再発行と利用停止は、対象通知メンバーの全セッションを同じDBトランザクション
内で失効させます。

## 権限

通知メンバー用セッションで利用できるのは専用のログイン、本人確認、ログアウトと、
次段階で追加する通知一覧・確認操作だけです。契約、キーワード、メール監視アカウント、
ログイン方法、他メンバーの管理APIではOWNER用セッションが必要です。

## 初回画面

未ログイン時はマーケティング用ランディングページではなく、次の2つだけを表示します。

- `Call Nowを設定する`: Google/Microsoft/Appleの本人確認へ進む
- `通知グループに参加`: Call Now IDとパスワードで通知メンバーとしてログインする

Team作成は従来どおり契約完了時に行い、ゲストホーム表示やログインだけでは作成しません。

## 次段階

Alert、リアルタイム配信、確認応答、通知先登録は別PRで実装します。Webアプリを閉じた状態
でのバックグラウンド通知は、この基盤だけでは保証しません。将来のAPNs、FCM、Web Pushを
Provider中立の配信モデルへ接続します。
